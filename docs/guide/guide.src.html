The short version EdgeMemory helps the people who handle purchase requests that break the normal rules. It remembers how similar problems were solved before, suggests the steps to take, says clearly when it has never seen a problem, and learns from every decision a person makes. It never approves anything on its own. A human always decides.
01 What is EdgeMemory?

A memory for the exceptions

Most purchase requests are routine. The ones that aren't (an expired certificate, a budget overrun, an approver on leave) take most of the time, and the know-how to fix them lives in people's heads and old emails.

The problem

In a company like Kaveri Precision Components (a made-up mid-size manufacturer in Hyderabad), every purchase request goes through a set of checks: Is there budget? Is the vendor in good standing? Is the right person available to approve? Is this a duplicate? Did the vendor's bank details change? Were enough quotes collected?

When a check fails, the request lands with a procurement analyst. They have to work out what to do: who to ask, what paperwork to collect, whether to hold the order. Usually someone solved the same problem before, but finding out how takes time. When several checks fail at once, the answer can be different from simply doing each fix.

What EdgeMemory does

  • Finds the precedents. For every check that failed, it looks up how people resolved that same problem before.
  • Checks they really apply. A precedent only counts if the situation matches: same problem, same cause, similar amount and category, and no policy change since.
  • Suggests a procedure. It combines the lessons into one list of steps, and every step links back to the real past cases behind it.
  • Says "I don't know" when it doesn't. If nothing matches, it sends the case to a person, with what is known and what isn't.
  • Learns from you. Every approve, edit, reject or resolve is remembered, so the next similar case is easier.

What it never does

  • It never approves, rejects or pays anything by itself. It only recommends; a person decides.
  • It never releases a payment.
  • It never removes a safety step (such as "hold the payment until the new bank account is confirmed by phone").
  • It never gives a confident answer to a problem it has never seen.
About the data Everything you see in this guide and in the app (the company, people, vendors, amounts and past cases) is synthetic: made up for the demo. Only synthetic data is ever sent to the AI services this build uses.
02 How it works

From request to decision

Every request goes through the same five steps. The first four are automatic and take about 10–20 seconds. The fifth is yours.

STEP 1ReadAn AI reads the request, emails and attachments (even messy ones like "1.9L" or Hinglish) and pulls out the facts.
STEP 2CheckSix fixed rules run: budget, vendor, approver, duplicate, bank, quotes. Plain code, no AI.
STEP 3RecallFor each failed check, memory finds past resolutions, and a verifier confirms each one really applies.
STEP 4ComposeThe lessons are combined into one procedure. A safety floor adds any step that must never be skipped.
STEP 5You decideApprove, confirm, edit, reject or resolve. The decision is remembered for next time.

Four ideas that make it different

IDEA 1

One problem at a time

A request with three failed checks isn't "one big unknown". EdgeMemory looks for a precedent for each check separately, so it can say "two of these three are familiar, one is new".

IDEA 2

Problems can change each other

Sometimes two problems together need a different fix. Example: an approver on leave plus a budget overrun means the delegate can't approve; it must go one level up. EdgeMemory learns these combinations from past decisions; nobody programs them in.

IDEA 3

Lessons grow up

A lesson backed by one case is tentative: you check each step. Once several cases agree it becomes established and can be approved in one click. If a reviewer overrules a lesson, it is revised. If policy changes, old lessons are flagged as out of date.

IDEA 4

Honest about the unknown

If any failed check has no real precedent, the case goes to a person, with what is known and what isn't. The goal is zero false confidence: never a confident answer that wasn't earned.

The five kinds of case

KindWhat it meansHow you review it
NormalEvery check passed.One click
KnownOne problem, and a precedent that applies directly.One click if the lesson is established; otherwise step by step
GeneralizedOne problem, and a precedent that applies with some differences (listed for you).Step by step
ComposedSeveral problems, each with a precedent. The procedure combines them, adjusted for how they interact.Step by step
UnknownAt least one problem has no real precedent.Goes to a person to resolve
The safety floor Some steps can never be removed by any lesson. For example: if a vendor's bank details changed, EdgeMemory always adds verify the bank account by phone and hold the payment. If the requester is related to the vendor, it always adds declare the conflict of interest. If a vendor's tax (GST) registration is cancelled, it always holds the order.

Behind the scenes: memory is Hindsight (by Vectorize). It stores each resolved case, merges similar cases into lessons, and keeps track of which cases each lesson came from, which is how every step can cite real case numbers.

03 Where to use it

Who it's for, and where it fits

Who it's for

  • Procurement operations analysts: the people who handle requests that fail the standard checks. This is who EdgeMemory is built for.
  • Approvers and team leads: they see a clear procedure with the reasons and past cases behind it, instead of a long email chain.
  • Finance controllers and auditors: every recommendation, citation, safety step and human decision is logged with a timestamp and can be exported.

Where it fits in your day

EdgeMemory sits next to the approvals queue you already have. Requests can come from a monitored approvals inbox or from an export of your existing system. For each exception, it adds a recommendation: the steps, a citation for every step, and what isn't covered.

How a team would start

  1. Load your history. Export the last year of resolved exceptions (what failed, what was done, why) into a simple spreadsheet format. EdgeMemory learns its first lessons from that. The demo starts exactly this way.
  2. Shadow mode. EdgeMemory recommends; analysts keep working as usual and compare.
  3. Step-by-step review. After about two weeks, analysts start ticking each recommended step.
  4. One-click review, lesson by lesson. As lessons become established, those cases can be approved in one click. Unknown cases always go to a person; that never switches off.

Other places the same idea could help

The approach (check each problem separately, learn how problems combine, learn from every human decision) could apply to other rule-heavy approval work, such as accounts-payable exceptions, IT change approvals or insurance claims. This build has only been built and tested for procurement.

Using real company data This hackathon build runs on free AI tiers and must only process synthetic data. A real deployment would use a paid, zero-data-retention AI setup (or the company's own AI provider) and a private memory store. The code is built so only one file changes for that.
04 Set it up

Install and start

About 15 minutes the first time. You need two programs, three free keys, and two terminal windows.

What you need

ItemDetails
Python 3.11 or newerRuns the engine and the API (the "back end").
Node.js 20 or newerRuns the website (the "front end").
Groq API key (free)The main AI model, openai/gpt-oss-120b. From console.groq.com.
Gemini API key (free)Backup AI models, used only if Groq fails. From Google AI Studio.
Hindsight Cloud keyThe memory. From Vectorize's Hindsight Cloud.

Step by step (Windows PowerShell)

  1. Open the project folder in PowerShell. 
    cd D:\EdgeMemory
  2. Add your keys. Copy the example settings file, then open .env in a text editor and paste your three keys between the quotes. 
    copy .env.example .env
  3. Install the back end (once). 
    python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
  4. Install the website (once). 
    cd web
npm install
cd ..
  5. Start the API and leave this window open. 
    .venv\Scripts\python -m uvicorn api.main:app --port 8000
  6. Start the website in a second PowerShell window and leave it open too. 
    cd D:\EdgeMemory\web
npm run dev
  7. Open the app at http://localhost:3000. Go to Demo, click Reset, then Seed. Seeding loads 37 past cases into memory and takes about 3 minutes.
On macOS or Linux, or if you have "make" The same steps are shortcuts: make setup installs, make api and make web start the two parts, and make test runs the automated tests. Use .venv/bin/python in place of .venv\Scripts\python.
How to tell it's running The website opens at localhost:3000. The Demo page shows how much free AI quota is left and the API response time. The API's own page is at localhost:8000/docs. To stop, press Ctrl+C in each window.
05 A tour of the screens

What you're looking at

Six pages, all in the top menu. The switch at the top right changes between light, dark, and your computer's setting.

Home and the queue

The home page explains EdgeMemory in one line and shows headline results from the benchmark. The numbers come straight from the scored test runs. Scroll down for how it works, then the queue: open requests grouped by kind, most urgent first (cases that need a person at the top). Click any row to open it.

The case page: seven stages

Opening a request shows how EdgeMemory reached its recommendation, in seven numbered stages. In demo mode they appear one after another, so you can follow the reasoning.

#StageWhat it tells you
1The requestVendor, amount, cost centre, and the original text. Important phrases (like a family link) are highlighted.
2Failed checksWhich of the six checks failed, and exactly why.
3How each problem was resolved beforeFor each failed check: whether a precedent applies, the past case numbers, and how mature the lesson is.

ButtonWhen you see itWhat happens

06 Guided walkthrough

Run the demo, step by step

This is the best way to test EdgeMemory and see it learn. It takes about 10 minutes. Go to Demo, click Reset then Seed, and wait about 3 minutes. Then click Run on each step in order.

1The hook: three problems at once
The request₹4.8 lakh, production line 3 is down, 6% over budget, the approver is on leave, and the vendor's bank details changed 12 days ago. You'll seeComposed, step-by-step. All three problems have precedents, and a past case of approver away + budget over changes the plan: it goes to the next-level approver, not the delegate. Payment is held until the bank is verified by phone. DoNothing yet. Come back to it at the end (pictured in section 05).
2A problem it has never seen
The request₹60,000 to a vendor whose quality certificate expired 6 days ago. Memory has no certificate cases yet. You'll seeUnknown and Escalate to a human, with "No verified precedent". DoClick Resolve. The form is pre-filled with a sensible answer. Save it. It becomes the first certificate lesson.
3One week later: the same problem again
The requestA different vendor, the same kind of expired certificate. You'll seeIt now recognises the problem and cites PR-DEMO-E1-01, the case you resolved in step 2. The lesson is tentative (one case), so the review is step by step. DoTick the three steps and click Confirm.
4Three weeks pass
What happensTwo more certificate cases are resolved the same way in the background, and the demo clock moves forward. DoOptional: open Lessons → step:vendor to see the lesson now backed by more cases, with the change highlighted.
5The lesson is established
You'll seeKnown, established (4 cases), and a single Approve button: one-click review. DoClick Approve.
6You overrule a lesson
The requestA "split shipment" from a vendor that once sent a duplicate invoice. You'll seeThe usual split-shipment lesson: link it to the main order and allow the split delivery. DoClick Reject. The form is pre-filled: this vendor's history means the claim can't be taken on trust. Save it. EdgeMemory records this as an override for this situation.
7It follows your correction
The requestAnother split shipment from the same vendor. You'll seeThe old steps are crossed out, and the procedure is now Reject request and Escalate to audit, citing PR-DEMO-E4-01, your decision in step 6. The original lesson still holds for other vendors. DoConfirm.
8An honest limit
The requestThe vendor's owner signs an email as the requester's brother-in-law. You'll seeThe family link is highlighted. Unknown: there is no precedent for a related party, so it goes to a person. The safety floor still adds Declare conflict of interest. DoNothing. This shows EdgeMemory refusing to guess.

It's working if…

  • Steps 2 → 3 → 5 show the same problem going unknown → tentative → established.
  • Step 7 follows your step-6 rejection instead of the old lesson.
  • Steps 2 and 8 go to a person instead of guessing.
  • The hook (step 1) and step 8 keep their safety-floor steps.
  • Every step's Why this step? shows real case numbers.
Small differences are normal The AI isn't perfectly repeatable, so a class or a step may occasionally differ from the pictures (for example "Known" instead of "Generalized"). Steps 2 and 8 must always go to a person, and step 7 must always recommend rejecting and escalating. Before recording a demo, click Reset and Seed again, because running the steps changes the memory.

Results on the test cases

EdgeMemory (C) was compared with: A, an AI with the policy but no memory; B, an AI with plain document search; and D, the same EdgeMemory pipeline with plain search memory instead of Hindsight. 24 made-up test cases; each approach ran once; the correct answers were locked before scoring.

Learning: when the test cases were replayed in date order with every decision remembered, EdgeMemory with Hindsight reached a one-click review on 8 of 22 exception cases, against 4 of 22 with plain search memory, and gave no false-confidence answers along the way.

Where it's weaker Plain search (B) handled the three "after a reviewer override" cases better. EdgeMemory sent two to a person and gave one an empty procedure. That problem has since been fixed and checked on the demo, but the published test numbers are from before the fix and weren't re-run. EdgeMemory also sends a few cases to a person that didn't strictly need it.

Free-tier limits

  • The main AI (Groq, free tier) allows about 200,000 tokens a day, refilling gradually. The full demo uses about 16,000.
  • The backup models (Gemini, free tier) allow 20 requests a day each.
  • The Demo page shows what's left. If it runs out, cases are sent to a person with "Memory unavailable" instead of a guess.

Good to know

  • All data is synthetic, and there is one domain (procurement) and a small sample of cases.
  • Time savings shown on the benchmark page are estimates from stated assumptions, not measurements.
  • The test answers were written by an AI labeller working blind, not checked by a person.
08 Troubleshooting

When something goes wrong

What you seeWhat to do
The website won't open at localhost:3000Check the website window is still running (npm run dev). Start it again if it stopped.
Pages load but show "Couldn't load…" errorsThe API isn't running. Start it in its own window (step 5 of setup) and refresh.
Every case says "Memory unavailable, escalating to a human"The memory service or the AI can't be reached. Check the internet connection and the keys in .env, then look at the API window for errors.
A step is stuck on "Running…" for more than a minuteThe free AI quota is probably used up for now. Check the quota on the Demo page; it refills gradually.
A case cites itself, or the demo looks different from this guideA step was run twice without resetting. Click Reset then Seed on the Demo page and run the steps in order.
A page shows an error after the computer was busy for a long timeStop the website window (Ctrl+C) and start it again with npm run dev.
The animations are distractingTurn on "reduce motion" in your computer's settings; the app switches its animations off.
Check the engine itself .venv\Scripts\python -m pytest -q runs 170 automated tests offline in a few seconds. They should all pass.
09 Glossary

The words, explained

WordMeaning
Purchase request (PR)A request to buy something. The six checks run on it.
Purchase order (PO)The document that commits the company to buy. "Hold PO" means don't issue it yet.
ExceptionA request that failed at least one check and needs a person's attention.
PrecedentA past case where people resolved the same kind of problem. Every recommended step cites one.
LessonWhat memory has learned from several precedents, in plain words.
Tentative / establishedA lesson from one case is tentative (check each step); one backed by several agreeing cases is established (one click).
OverrideA reviewer rejected or changed what a lesson said for a specific situation. Later similar cases follow the reviewer.
InteractionTwo or more problems happening together, where the right fix differs from doing each fix separately.
Safety floorSteps no lesson can remove, such as holding payment until a changed bank account is confirmed by phone.
False confidenceGiving a confident procedure for a problem with no real precedent. The target is zero.
EscalateSend the case to a person to decide.
Cost centreA department's budget line (for example CC-MACH, machining).
DelegateThe person allowed to approve while the usual approver is away, up to a set amount.
Line downA production line has stopped, which makes the request urgent.
Sole sourceOnly one approved vendor can supply the item, so the usual three quotes aren't possible.
GSTIndia's Goods and Services Tax. A cancelled GST registration is a serious vendor problem.
Lakh (L)Indian unit: 1 lakh = ₹1,00,000. So ₹4.8L = ₹4,80,000.
HindsightThe memory service (by Vectorize) that stores cases, merges them into lessons, and tracks where each lesson came from.
Synthetic dataMade-up data. Kaveri Precision Components and everything about it is fictional.
